# Formal model of the presets, key builders and profiles (Lean 4)

A Lean 4 model of the preset step lists in `src/presets.rs`, the profile pipeline in
`src/pipeline.rs`, and the steps they are built from: `canonicalize`,
`canonicalize_strict`, `strip_obfuscation`, `strip_format`, `ml_normalize`, `search_key`,
`catalog_key`, `sort_key` and `skeleton_key` under each digit policy, and the eight named
profiles. The model is validated against the built library by differential testing before
any proof or counterexample counts. Properties the code and docs claim are then proved, or
refuted with a minimal counterexample that is reproduced on the library.

> **Status.** Nothing here is fixed yet. Seven findings, each reproduced on the library
> (`repro/`), with a proposed fix modelled in `Presets/Fixes.lean` and checked there.

Written against `main` at `595fbda` (0.16.0 + unreleased, `KEY_SCHEMA_VERSION` 10). Line
numbers (`presets.rs` L2103) refer to that commit. Core Lean 4.34.0 only, no Mathlib.

## The model

Characters are code points (`Nat`). The **input alphabet** is 38 code points, one or two per
class a step branches on:

| Class | Code points |
|---|---|
| inert / composing ASCII letters | `a` `e` `u` `y` `l` |
| the prototype sources | `I`, `1`, `\|` |
| uppercase ASCII | `A` |
| whitespace and controls | SPACE, TAB, LF, BS, NUL |
| combining marks | U+0301 (ccc 230), U+0308 (ccc 230), U+0338 (ccc 1, a negation overlay) |
| precomposed letters | U+00E9, U+00FD |
| case fold to several code points | U+03B0 (to U+03C5 U+0308 U+0301) |
| confusable and transliteration differ | U+03C5 (`u` / `y`), U+0440 (`p` / `r`), U+00A5 (`Y` / `JPY`) |
| a symbol whose confusable row is a letter | U+00A2 (`c`) |
| a relation, a surviving negation base | `=` (with U+0338 composes to U+2260) |
| no row until case-folded | U+A760 (folds to U+A761, whose row is `w`) |
| transliterates to a confusable source | U+01C1 (to `\|\|`) |
| a `tr39`-only row after a case fold | U+0100 (folds to U+0101, whose `tr39` row is U+00E3) |
| invisibles | U+200B, U+00AD, U+034F (CGJ), U+FE0F (VS16), U+E000 (PUA), U+202E (RLO) |
| compatibility form | U+FF21 |
| conjoining Hangul | U+1100 (L), U+1161 (V): L + V composes to U+AC00, two starters |

The **domain** is the closure of the alphabet under every per-character map a step applies
and under canonical composition: 104 code points. Every per-character map is read from the
library by `scripts/gen_tables.py`, not written by hand:

| Table | Source |
|---|---|
| `foldT` | `disarm.fold_case(ch)` |
| `conf_numeric`, `conf_tr39`, `conf_preserve` | `TextPipeline(confusables=True, digit_policy=p)(ch)`: the raw single-pass row (`lookup_with_policy`, confusables.rs L129) |
| `translitP`, `translitI` | `disarm.transliterate(ch, errors="preserve" / "ignore")` |
| `keepsScript` | `disarm.detect_scripts(ch)` |
| `nfdT`, `nfkdT`, `cccT`, `compose` | `unicodedata`, checked against `disarm.normalize` |
| `widenKeys` | `src/tables/data/excluded_compositions.tsv` |

The strip predicates (zero-width, bidi, control, whitespace, blank-render, tags, VS,
noncharacters, PUA, `occupies_cell`, `survives_as_a_negation_base`) are restated from the
Rust and checked against the public strip functions before the tables are written.

The context-sensitive code is transcribed branch by branch:

| Rust | Lean |

**Not modelled.** `demojize` is the identity on the domain, which holds no emoji; the
cross-script mark strip is the identity (every mark in the domain is `Inherited`); the
subdivision-flag carve-out needs U+1F3F4, which is not in the domain; `lang` is `None`
throughout; the NFKC output ceiling and every error path. The model says nothing about
performance.

## Validation: differential testing

```bash
lake build                          # this directory
python3 scripts/difftest.py         # --exhaustive 3 --small 4 --random 100000 --seed 1016
```

Every word goes through all 52 surfaces: the seven builders under each of the three digit
policies, `strip_format`, `ml_normalize` with and without the case fold, the eight profiles
(three also under `tr39`), and 17 single steps that have a public function of their own
(`normalize` x3, `fold_case`, `strip_accents`, `strip_bidi`, `strip_zero_width_chars`,
`strip_control_chars`, `collapse_whitespace`, `strip_zalgo` x2, `strip_pua`,
`normalize_confusables` x2, `TextPipeline(resolve_deletions=True)`, `transliterate` x2).

* every word of length 3 or less over the 38-letter alphabet (56,355 words);
* every word of length 4 over the 23-letter sub-alphabet the findings live in (279,841);
* 100,000 random words of length 12 or less over the whole alphabet.

**Result: 22,682,192 of 22,682,192 comparisons agree** (436,196 words x 52 surfaces). Code points are compared exactly.

The model was wrong three times on the way there, each time about something the library
does that the docs do not state, and each is now in the model: compose-at-lookup emits the
composition-excluded U+0344 for a diaeresis + acute cluster (through the widening map), the
transliterator composes at lookup, and it inserts a space before a Hangul syllable when the
last character written is alphanumeric.

Because the model agrees with the library on every word `Bounded.lean` quantifies over, each
bounded result about the *current* model is a result about the built library on those words.

## What is proved

### For every input and every step list, by induction (`General.lean`)

No `native_decide`, no `sorry`. `Axioms.lean` shows at most `propext`, `Quot.sound` and
`Classical.choice`.

| Theorem | Statement |
|---|---|
| `run_fixed_of_all_fixed`, `run_idem_of_image_fixed` | **The stable-image criterion.** A pipeline whose output is a fixed point of every one of its steps is idempotent. This is the argument every idempotence comment in `presets.rs` makes. |
| `run_not_idem_of` | Its contrapositive at a point: if a second pass differs, some step moves the first output. Every finding below names that step. |
| `filter_idem`, `filter_comm`, `filter_filter_and`, `filter_run_comm` | The pure strips (`strip_bidi`, `strip_zero_width`, `strip_control`, `strip_pua`, comparison `strip_invisible`) are idempotent and commute; any run of them is one filter on the conjunction, so their relative order never matters. |
| `flatMap_idem` | A per-character map whose images are its own fixed points is idempotent. The case fold and the confusable pass are not such maps, which is why they sit inside loops. |
| `comp_idem_of_comm` | Two idempotent, commuting steps compose to an idempotent step. |
| `fixLoop_stable` | The bounded fixed-point loop returns a fixed point of its body whenever the body stops moving before the fuel runs out. |
| `applySteps_eq_run` (`Findings.lean`) | A preset's step list is `General.run` of its steps, so the lemmas above apply to it. |

### On the model's words, by kernel evaluation (`Findings.lean`, `decide`)

Every counterexample below is a closed statement checked by the kernel, about one word of 1
to 3 code points, together with the step that moves the first output (`*_moved_by_*`) and
the same word through the fixed variant.

### Bounded, exhaustively (`Bounded.lean`, `native_decide`, about 2 minutes)

`W3` = every word of length at most 3 over the input alphabet (56,355); `S4` = every word of
length 4 over the findings' sub-alphabet (279,841).

| Theorem | Result |
|---|---|
| `idem_W3`, `idem_S4` | **Holds.** `canonicalize`, `canonicalize_strict` and `catalog_key` under all three policies, `search_key` and `sort_key` under the default, `strip_format`, and `code_context`, `library_catalog_key_eu` (also `tr39`), `rag_ingest`, `scholarly_cyrillic_iso9`, `search_index` are fixed points. |
| `guard_sound_W3`, `guard_sound_S4` | **Holds.** The fast-path guard of `run_static` agrees with the full step list for all ten shipped step lists. |
| `skeleton_key_failures` | **Fails** on 5,092 of `W3` (5,174 under `tr39`): Finding 1. |
| `search_key_policy_failures`, `sort_key_policy_failures` | **Fail** on 8,206 each under `tr39` and `preserve`: Finding 2. |
| `profile_failures` | **Fail**: `llm_guardrail` 331, `ml_corpus_normalize` 80, `normalize_web_input` 112: Findings 3 and 4. |
| `strip_obfuscation_failures`, `ml_normalize_failures` | **Fail** on 1 and 2 words (the jamo): Finding 4. |
| `fixes_idem_W3`, `fixes_idem_S4` | **Holds** for every proposed fix, under every policy. |
| `skeleton_fixed_nfc` | The fixed `skeleton_key` output is NFC on every word; the current one is not. |
| `targeted_insufficient` | The targeted profile fix (one more mark strip, the strips ahead of `NORMALIZE`) still fails `normalize_web_input` on 28 words, which is why the proposal iterates instead. |

## Findings

### Finding 1: `skeleton_key` is not a fixed point, and misses the confusable pair it exists to catch

**Class (a), code bug. Severity: medium.** `skeleton_key` is a spoof key: its only job is
to make two confusable identifiers collide, and its own comment says "a key that is not a
fixed point is not a key" (presets.rs L2096-L2097).

```bash
python3 repro/f1_skeleton_key.py
# skeleton_key[numeric] U+03B0              '\u03b0'        -> 'u\u0308\u0301' -> '\u01d8'     NOT A FIXED POINT
# skeleton_key[numeric] yen + acute         '\xa5\u0301'    -> 'y\u0301'       -> '\xfd'       NOT A FIXED POINT
# skeleton_key[numeric] e + CGJ + acute     'e\u034f\u0301' -> 'e\u0301'       -> '\xe9'       NOT A FIXED POINT
# skeleton_key[numeric] I-dot + U+20D2      '\u0130\u20d2'  -> 'i\u0307\u20d2' -> 'i\u20d2\u0307' NOT A FIXED POINT
# (the same under tr39 and preserve)
# yen + acute keys to 'y\u0301' ; Y-acute keys to '\xfd' ; collide: False
# output is NFC: False
```

U+00A5 YEN SIGN + U+0301 renders as U+00DD. `canonicalize` collides the two; the spoof key does not.
Model: `skeleton_not_idem`, `skeleton_misses_pair`, `skeleton_cgj`, and
`skeleton_moved_by_nfkc` names the step.

**Root cause.** The builder normalizes once, first (L2076), and three later steps undo
it with nothing recomposing afterwards: the confusable fold and the case fold emit
decomposed sequences (U+03B0 case-folds to three code points; the fold turns U+00A5 into `Y`
beside a mark NFKC has already passed), and `StripInvisible`, `StripControl` and
`StripZeroWidth` remove characters that sat between a base and its mark (L2081, L2105-L2106).
By `run_not_idem_of`, the second pass differs because the output is not a fixed point of
the leading `Nfkc`. The output is not even in canonical order (`i` U+0307 U+20D2).
`canonicalize` has the NFC sandwich for exactly this (#416/#434); `skeleton_key` never got
one. Library sweeps: 8 scalars, 1,076 of the `pairs` strings, 1,394 of `pairs2`, and
57,948 of `F1`, 5,372 of `F2` and 39,900 of `F3`.

**Minimal fix** (`skeletonKeyFixedSteps`): move `StripControl` and `StripZeroWidth` up to
just after `StripInvisible`, fold with `ConfusablesNfcFixedPointCtx` instead of
`ConfusablesCtx`, and close the case-fold loop with NFC:
`FixedPoint(&[FoldCase, ConfusablesCtx("latin"), Nfc])`. The prototype fold still sees
cased text, so the #650 trade is untouched. Checked: `fixes_idem_*`, `skeleton_fixed_nfc`,
`skeleton_fixed_pair` (the pair now collides). **Moves stored keys**: `skeleton_key`
shipped in 0.16.0; the fix changes 78,706 of the difftest's 436,196 words (80,753 under `tr39`); 78,453 of them are words on
which the current key is not a fixed point. The other 253 are the same defect seen from
the other side: `I` NUL U+0308 keys to `l` U+0308 today while U+00CF keys to U+00EF, and
the fix gives both U+00EF. A `KEY_SCHEMA_VERSION` event,
absorbable by the unreleased 10.

### Finding 2: `search_key` and `sort_key` are not fixed points under a digit policy

**Class (a), code bug. Severity: low to medium** (opt-in parameter; the default is
unaffected).

```bash
python3 repro/f2_policy_keys.py
# search_key[tr39] Latin capital VY     '\ua760' -> '\ua761' -> 'w'     NOT A FIXED POINT
# search_key[tr39] lateral click        '\u01c1' -> '||'     -> 'll'    NOT A FIXED POINT
# sort_key[tr39] Latin capital VY       '\ua760' -> '\ua761' -> 'w'     NOT A FIXED POINT
# sort_key[tr39] A with macron          '\u0100' -> '\u0101' -> '\xe3'  NOT A FIXED POINT
# (the same under preserve; every word is a fixed point under numeric; catalog_key is a
#  fixed point under every policy)
```

Model: `search_vy`, `search_click`, `sort_macron`, `search_vy_numeric`,
`search_moved_by_prefold`.

**Root cause.** Under any policy but `numeric`, `Step::PolicyPreFold` (presets.rs L1480,
L1641) runs the whole Latin confusable fold once, on the raw text, and these two builders
have no fold of their own after it. Three later steps then produce fold sources the
pre-fold never saw: `FoldCase` (a capital with no row, whose lowercase has one: U+A760,
U+0100 under `tr39`), and `Transliterate` (which emits the ASCII sources `|`, `"`, `` ` ``).
`catalog_key` survives because its own fold sits inside the `FixedPoint` after `FoldCase`.
Library sweeps: 62 (`search_key`) and 171/172 (`sort_key`) single scalars; 682 and
1,879/1,890 of the `pairs` strings.

**Minimal fix** (`runPolicyFixed`): under a non-default policy, iterate the builder to a
fixed point in `run_static` (L950), bounded by `CONFUSABLE_FIXED_POINT_ITERS`; the default
path, and every default key, is untouched. Checked: `fixes_idem_*`. **Moves stored keys**
only for callers passing `tr39`/`preserve`, and only on words that were not fixed points
(116,111 of the difftest's words for `search_key` and 115,996 for `sort_key`, every one
of them a word that is not a fixed point today).

### Finding 3: `llm_guardrail` and `ml_corpus_normalize` keep a negation overlay, then orphan it

**Class (a), code bug. Severity: low to medium.** `tests/test_profiles_are_fixed_points.py`
asserts every profile is a fixed point "for every code point that exists"; it is not for
two-character strings.

```bash
python3 repro/f3_negation_overlay.py
# llm_guardrail cent + U+0338           '\xa2\u0338'       -> 'c\u0338' -> 'c'  NOT A FIXED POINT
# llm_guardrail union + U+0338          '\u222a\u0338'     -> 'u\u0338' -> 'u'  NOT A FIXED POINT
# llm_guardrail for-all + U+20D2        '\u2200\u20d2'     -> 'a\u20d2' -> 'a'  NOT A FIXED POINT
# llm_guardrail PUA + U+0338            '\ue000\u0338'     -> '\u0338'  -> ''   NOT A FIXED POINT
# ml_corpus_normalize PUA + U+0338      '\ue000\u0338'     -> '\u0338'  -> ''   NOT A FIXED POINT
# ml_corpus_normalize plane-15 PUA + U+20D2 '\U000f0000\u20d2' -> '\u20d2' -> '' NOT A FIXED POINT
```

Model: `guard_cent`, `corpus_pua`, `guard_moved_by_mark_strip`.

**Root cause.** #749 keeps one U+0338/U+20D2 on a base that is not alphanumeric and
"survives the pipeline" (`survives_as_a_negation_base`, transliterate.rs L1553). Survival
is judged per character, not per pipeline, and the profile order breaks it twice:
`STEP_ORDER` runs `strip_zalgo`/`strip_accents` (pipeline.rs L130, L151) **before** the
confusable fold (L162), which turns the symbol base into a letter (U+00A2 -> `c`, U+222A -> `u`),
and **before** `strip_pua` (L173), which deletes the base outright. The next pass sees
strikethrough on a letter, or a mark with no base, and strips it. The presets are immune
because they order it the other way: `strip_obfuscation`'s `StripAccents` follows its fold,
and every comparison preset strips PUA before any mark step. Library sweeps: 6,485 of the
`pairs` strings, 6,488 of `pairs2`, 60 of `F1` and 1,008 of `F2` for `llm_guardrail`;
6,400, 6,400 and 34 for `ml_corpus_normalize` (the BMP PUA, once per overlay).

**Minimal fix.** Iterate `Pipeline::process` to a fixed point (`profileFixed`), which also
closes Finding 4 for the profiles. The targeted alternative -- one more mark strip after
`STRIP_PUA` -- closes this finding (`profileStepsTargeted`) but not all of Finding 4
(`targeted_insufficient`). Changing `survives_as_a_negation_base` instead would move
`ml_normalize` and `search_key` keys too. Profiles are not in the key-stability fixture;
on the difftest's words the iteration moves 7,256 (`llm_guardrail`), 2,321
(`ml_corpus_normalize`) and 3,529 (`normalize_web_input`), every one non-idempotent today,
and no word of the other five profiles.

### Finding 4: a character removed after the last normalization separates two that compose

**Class (a), code bug. Severity: low.** Five surfaces, all documented or tested as fixed
points.

```bash
python3 repro/f4_separated_composition.py
# strip_obfuscation L NUL V              '\u1100\x00\u1161'   -> '\u1100\u1161' -> '\uac00' NOT A FIXED POINT
# ml_normalize L ZWSP V                  '\u1100\u200b\u1161' -> '\u1100\u1161' -> '\uac00' NOT A FIXED POINT
# ml_corpus_normalize L BS V             '\u1100\x08\u1161'   -> '\u1100\u1161' -> '\uac00' NOT A FIXED POINT
# llm_guardrail L ZWSP V                 '\u1100\u200b\u1161' -> '\u1100\u1161' -> '\uac00' NOT A FIXED POINT
# normalize_web_input e BS acute         'e\x08\u0301'        -> 'e\u0301'      -> '\xe9'   NOT A FIXED POINT
# normalize_web_input c NUL cedilla      'c\x00\u0327'        -> 'c\u0327'      -> 'c'      NOT A FIXED POINT
# normalize_web_input I PUA acute        'I\ue000\u0301'      -> 'I\u0301'      -> '\xcd'   NOT A FIXED POINT
# canonicalize, canonicalize_strict, sort_key, search_key, catalog_key: fixed points on the same words
```

Model: `obf_jamo`, `ml_jamo`, `guard_jamo`, `web_bs`, `web_pua`, `obf_moved_by_nfkc`.

**Root cause.** The #416 lesson ("a base+mark left adjacent by a stripped invisible"), in
the places it was not applied. `strip_obfuscation` strips controls after its last
normalizing step (presets.rs L1999, after `StripAccents` L1995); `ml_normalize` strips
controls and zero-width characters after its last one (L1263-L1265); the pipeline runs
`STRIP_CONTROL`, `STRIP_ZERO_WIDTH` and `STRIP_PUA` after `NORMALIZE` and the confusable
fold (pipeline.rs L169-L173), and `normalize_web_input` does not resolve deletions, so a BS
is only stripped. A conjoining jamo pair composes with no mark involved, which is why the
mark strips of `strip_obfuscation` and `ml_normalize` do not hide it. `c` NUL cedilla shows
the worst case: the composition exposes a confusable (U+00E7 -> `c`) that the fold has already
passed. Library sweep `F3` (jamo): 3,990 for `strip_obfuscation`, 11,970 for `ml_normalize`,
15,960 for `llm_guardrail`, 19,950 for `ml_corpus_normalize`, 23,940 for
`normalize_web_input`; and `F1` (base, removable character, mark): 1,158 for
`normalize_web_input`, e.g. `a` ZWSP U+0300.

**Minimal fix.** `NfcIfNonAscii` at the end of `strip_obfuscation` and `ml_normalize` (as
`sort_key` has, L1714); for the profiles, the iteration of Finding 3. Checked:
`fixes_idem_*`. **Moves stored keys** for `strip_obfuscation` and `ml_normalize` only on
words that were not fixed points (72 and 130 of the difftest's words, every one non-idempotent today).

### Finding 5: `PRESETS` is not what the presets run

**Class (c), inconsistency. Severity: low** (introspection only, nothing executes it -- but it
is documented as the thing to audit and to build equivalent pipelines from).

`PRESETS["canonicalize"]` is "what `canonicalize()` runs" (`_presets.py` L1060) and
`docs/api/pipelines.md` says to use it "to audit exactly which transforms a preset applies,
or to build equivalent `TextPipeline` configurations". Executing each list literally with
the public function each step names:

```bash
python3 repro/f5_presets_mirror.py
# canonicalize         a BS b            preset='b'          PRESETS executed='ab'
# canonicalize         a + acute x4      preset='\xe1'       PRESETS executed='\xe1\u0301\u0301'
# strip_obfuscation    grinning face     preset='\U0001f600' PRESETS executed='grinning face'
# search_key           ab + PUA          preset='ab'         PRESETS executed='ab\ue000'
# sort_key             ab + VS16         preset='ab'         PRESETS executed='ab\ufe0f'
# ... (15 mismatches over 6 words x 8 presets)
# skeleton_key in PRESETS: False
# resolve_deletions in any PRESETS list: False
# strip_obfuscation lists demojize: True
# canonicalize_strict lists strip_zalgo before confusables: True
# search_key / catalog_key / sort_key list strip_invisibles: False
```

**Root cause.** `_presets.py` L1071-L1215 is a hand-maintained mirror, and
`tests/test_mutant_killers.py::test_preset_steps_exact` pins it to a second hand-written copy
rather than to the Rust. It missed #937 (`resolve_deletions`, every list), #805
(`strip_invisibles` in the three key builders), #835/#862 (`drop_repeated_marks`, and the
cap's move after the fold in `canonicalize_strict`), #910 (the `demojize` step removed from
`strip_obfuscation`), #807 (`sort_key`'s cap), #467 (`catalog_key`'s fixed point), and has
no `skeleton_key`. Its comment still says the cap is "2 per base"; it is 3 (#788).

**Minimal fix.** Generate `PRESETS` from the Rust step lists (an `explain()` per preset, the
way `TextPipeline.steps` reads `STEP_ORDER`) and assert equality in the test; failing that,
update the eight lists and add `skeleton_key`. No key moves.

### Finding 6: the preset output ceiling is neither an output bound nor neutral to input size

**Class (b)/(c). Severity: low to medium** (resource-limit contract).

`docs/api/exceptions.md` and the 0.15.0 changelog: "Every preset now raises
`ResourceLimitError` above 10 MiB of produced output", "The cap is on produced output, so
ordinary text cannot reach it"; `src/limits.rs`: "disarm does not cap raw input size".

```bash
python3 repro/f6_output_cap.py
# (a) ml_normalize: 10,400,000 bytes in -> 106,599,999 bytes out, no error (limit 10,485,760)
# (b) canonicalize(11 MiB of 'a'): 11534336 chars, accepted
#     canonicalize('"' + 11 MiB of 'a'): ResourceLimitError: normalization expanded the input to 11534337 bytes, ...
#     search_key('A' + 11 MiB of 'a'): ResourceLimitError: normalization expanded the input to 11534337 bytes, ...
```

**Root cause.** The check sits on the `Nfkc` arm only and compares the *absolute* output
size (presets.rs L319-L331). (a) Steps after it amplify unchecked: `ml_normalize`'s
`Demojize` by up to 10x per scalar after NFKC (U+1FAF0, 4 bytes, is named in 40), measured
by `search/amplification.py` -- the "amplification a caller's own input-size check cannot
foresee" that `limits.rs` gives as the reason for the cap. (b) An input over 10 MiB that
NFKC does not grow at all is rejected, with a message saying it "expanded", whenever the
fast-path guard does not return it first -- so acceptance of a large ordinary document
depends on whether one byte of it is actionable.

**Minimal fix.** Cap the growth, not the size: `out.len().saturating_sub(input.len()) >
MAX_NORMALIZE_OUTPUT_BYTES` in the `Nfkc` arm, and apply the same growth check to
`Demojize` (and `Transliterate`) in the preset path. Or correct the three documents to say
what is bounded. No key moves.

### Finding 7: documented properties that do not hold

**Class (b), doc overclaim. Severity: low**, except (d), low to medium.

```bash
python3 repro/f7_doc_claims.py
# (a) ml_normalize(U) = ''  ml_normalize(S) = ''  ml_normalize(U + S) = 'flag: united states'
# (b) {'catalog_key': "'ab'", 'search_key': "'ab'", 'sort_key': "'ab'"}
# (c) ml_corpus_normalize(two CJK ideographs) = '\u4e2d\u6587'
# (d) search_key(cyrillic 'paypal', digit_policy='numeric') = 'raural'  sort_key: 'raural'
# (d) search_key(cyrillic 'paypal', digit_policy='preserve') = 'paypal'  sort_key: 'paypal'
# (d) search_key('|' '"' '`', digit_policy='tr39') = ['l', "''", "'"]  default: ['|', '"', '`']
# (d) skeleton_key('I') = 'l'
# (e) strip_obfuscation docstring names demojize: True
#     strip_obfuscation(grinning face) = '\U0001f600'
```

* **(a) The empty-key census.** Every builder's docstring and `docs/limitations.md`: "N
  single characters reduce to `""` here, and so does every string built from them". False
  for `ml_normalize`: two regional indicators each key to `""` and together name a flag
  (259 such pairs, `search/empty_census.py`). Holds for the other seven builders over every
  pair of their empty sets. Fix: say "most strings", or except the regional indicators.
* **(b)** `catalog_key`, `search_key` and `sort_key` docstrings (`_presets.py` L360, L487,
  L648): "Private-use characters survive into the key". Since #805 all three strip the whole
  PUA (137,468 code points of their census are PUA). Fix: delete the sentence.
* **(c)** `docs/api/pipelines.md` L331 lists `ml_corpus_normalize` output as "ASCII"; it has
  no transliteration, and 251,559 scalars in planes 0-3 and 14 give non-ASCII
  (`search/ascii_profiles.py`). The other three "ASCII" profiles are ASCII on every scalar.
  The same table's step lists predate `strip_pua`, `resolve_deletions` and the second
  confusable pass, and the `list_profiles()` output shown omits `code_context`.
* **(d) `digit_policy` on the builders with no fold of their own.** The notes say the policy
  "folds digit variants on the raw text" (L389, L514, L675). Under `tr39` *or `preserve`*
  it runs the whole Latin confusable table (the #885 pre-pass), so `search_key` and
  `sort_key` -- documented as having "no confusables step" -- fold Cyrillic `\u0440\u0430\u0443\u0440\u0430l` onto
  `paypal`, and rewrite `|`, `"` and `` ` ``, which `docs/limitations.md` ("Five surfaces
  rewrite printable ASCII") says they never do and which it says no surface but five does
  (`skeleton_key` also rewrites `I`, and `0`/`1` under `tr39`). A caller choosing
  `preserve` -- the policy whose name promises to leave numerals alone -- gets a homoglyph
  fold of the whole key. Model: `search_er_preserve`, `sort_er_preserve`. Fix: document it,
  or restrict the pre-fold to the digit rows.
* **(e) Step lists in docstrings.** `strip_obfuscation` (L953) still lists `demojize`
  (removed by #910); `canonicalize_strict` puts `strip_zalgo` before `confusables` (moved
  after it by #862); `canonicalize` omits the repeated-mark drop, and its Rust step comment (presets.rs L1119) says the cap is 2 (it is 3, #788); none
  of the seven lists `resolve_deletions` (#937); `ml_normalize` omits the second `demojize`.
  The Rust doc comments in `src/presets.rs` and `src/api/presets.rs` carry the same drift,
  and `docs/api/pipelines.md` repeats it.

## Not confirmed, or not reachable

* **`Actionable::union` drops `prototype`** (presets.rs L646-L676: every field is ORed but
  `prototype`). A `FixedPoint` containing `PrototypeFold` would let the fast path return `I`
  unfolded. No shipped list has one, so it is latent. Model: `union_drops_prototype`,
  `guard_skips`, `steps_change`. Fix: `self.prototype |= o.prototype;`.
* **The fast-path audits leave out `skeleton_key`** (`all_presets()` in the presets.rs
  tests, and the tier-3 `fast_path_nonascii_exhaustive`). `guard_sound_W3`/`_S4` check it on
  the model's words and find nothing, which is evidence, not a proof over all scalars.
* **`normalize_confusables` can return a composition-excluded code point.** A diaeresis +
  acute cluster with no base comes back as U+0344 (the widening map composes it), which is
  not NFC. Outside this area; every preset renormalizes after the pre-fold, so no preset
  output shows it.
* **`strip_format` keeps two VS16 after one base** (`is_presentation_base` accepts a
  selector as a base). Idempotent and rendering-neutral; noted only.

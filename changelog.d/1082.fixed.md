- **The npm and JVM packages carry the core they are released with (#1082).** The
  npm `disarm@0.17.1` and the Maven Central 0.17.1 artifacts were built against core
  0.17.0, so they do not contain #1080's fix: `separator=" "` still raises there. The
  binding publish workflows waited for any core matching the glue's `0.MINOR` pin, and
  on a patch release the previous patch already matches, so they built and published
  before the new core reached crates.io. They now wait for the exact version the tag
  releases, and every publish build pins its lockfile to it or fails. The PyPI wheels
  and the crate were not affected, and 0.17.1 was never published to RubyGems, because
  the gem's own tests caught it. Separately, every npm release checked back to 0.14.1
  shipped an unoptimised debug build as `disarm.linux-x64-gnu.node`, about 40 MB beside
  2.4–2.8 MB release builds for the other platforms: the publish job recompiled the
  addon to regenerate its JavaScript loader and wrote the result over the release
  build. It no longer compiles anything, and it checks that the prebuilds it publishes
  are the ones the build matrix made.
